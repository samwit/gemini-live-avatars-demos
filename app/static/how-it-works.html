🧭 How it works

gemini-3.8-live · Live Avatar

From your voice to a talking face, and back, in about a second.

Every demo in this app is the same three-part system: a browser that captures you and plays the avatar, a small Python server that holds the credentials and runs the tools, and Gemini 3.8 Live, which listens, thinks, calls tools and renders the avatar's video.

1 · The big picture

your input going up the avatar coming back tool calls & UI updates

2 · One turn, step by step (The Note Taker)

You say something. Gemini answers out loud and, at the same time, calls note-taking-tool in the background. The avatar never pauses while the notes are being written.

sequenceDiagram
  autonumber
  actor You
  participant B as Browser
  participant S as Python server
  participant G as Gemini 3.8 Live
  You->>B: 🎙️ "Mum's party is Saturday, 20 people, garden theme…"
  B->>S: 16 kHz PCM (binary WebSocket frames)
  S->>G: send_realtime_input(audio)
  G-->>S: input_transcription (what you said)
  G-->>S: tool_call: note-taking-tool {title, points, action_items}
  par The avatar keeps talking
    G-->>S: fMP4 video chunks + output_transcription
    S-->>B: [0] + fMP4 → MediaSource buffer
    B-->>You: 🎭 lip-synced reply "Lovely! Who's baking the cake?"
  and The tool runs in the background (NON_BLOCKING)
    S->>S: note_taking_tool(args) in Python
    S-->>B: {"type":"ui","event":"note",…}
    B-->>You: 📝 handwritten notes appear
    S->>G: tool_response (scheduling = SILENT)
  end
  G-->>S: turn_complete
  Note over G,B: Between turns the video keeps streaming: the avatar idles, blinks and listens.

3 · What's actually in the avatar stream

Turning on response_modalities=["VIDEO"] makes the model send one continuous fragmented-MP4 file, in ~16 KB pieces, from the moment you connect. The voice is already inside it, so lip sync is free: the browser just appends every piece to a MediaSource.

4 · Three kinds of tools

⏸️ Blocking

The model waits for your answer. Use it for quick lookups and anything the reply depends on.

Appraiser: issue_certificate · Interrogation: confess (Python refuses unless 3 clues are found)

⏳ Async · WHEN_IDLE

behavior: NON_BLOCKING. The avatar keeps talking; the result is brought up at the next natural pause.

Appraiser: consult_auction_archives (takes 6 s)

🤫 Async · SILENT

Fire and forget. The result goes into context but isn't spoken about. Perfect for UI side effects.

Note Taker: note-taking-tool · Polyglot: add_vocab · Interrogation: update_composure

5 · Browser ⇄ server protocol

One rule: binary frames are media, text frames are JSON.

DirectionMessage
→ serverbinary: mic PCM 16 kHz
→ server{"type":"start","options":{…}}
→ server{"type":"image","data":b64} · {"type":"text"} · {"type":"action"}
← browserbinary: [stream byte][fMP4 chunk]
← browsertranscript · turn_complete · interrupted · tool · ui · error

The stream byte lets one socket carry two avatars (the Debate demo).

6 · Where it lives in the code

  • app/browser_link.py the protocol above

  • static/js/avatar-player.js the browser core: MSE + live-edge chasing
  • static/js/pcm-worklet.js mic → 16 kHz PCM
  • static/js/live-client.js socket + echo gate
